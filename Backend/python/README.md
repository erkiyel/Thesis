# Forecast service

The PHP API starts `forecast.py` for workbook validation and monthly Linear Regression. Install its dependencies in the backend-local virtual environment:

```powershell
python -m venv Backend/.venv
Backend/.venv/Scripts/python.exe -m pip install -r Backend/python/requirements.txt
```

PHP uses `Backend/.venv/Scripts/python.exe` automatically on Windows. Set the server-side `ONCOPHIL_PYTHON` environment variable when the virtual environment is elsewhere. The uploaded, validated historical workbook rows and non-schema forecast metadata are stored under `Backend/runtime/`, outside the PHP document root and ignored by Git. Back up that directory if these local imports and evaluation metrics must survive moving the backend host.

System sales include only orders whose latest payment is paid and whose order status is delivered. When an Excel import is selected, its rows are combined with those eligible system sales; imports should cover pre-system periods to avoid overlapping and double-counting sales. Both sources are grouped by medicine and calendar month, so multiple transactions in one month make one observation. The four-month minimum counts distinct calendar months with recorded source rows. Months absent from the source remain absent rather than being invented as zero-sales observations; calendar-month ordinals preserve gaps in the regression time index. Medicine names are matched to inventory after Unicode normalization, case folding, and removal of punctuation and spacing. Ambiguous inventory names are rejected rather than linked arbitrarily; names with no inventory match remain historical-only.

Forecasting remains nonnegative ordinary least-squares Linear Regression. Candidate comparisons include Linear Regression, trend plus annual seasonality Linear Regression, a deterministic NumPy/Python Random Forest, and additive Holt-Winters. Candidate comparison uses an earlier chronological validation slice; each candidate's reported out-of-sample comparison also uses the same separate trailing 20% chronological test holdout (rounded up, at least one month). Linear Regression remains the production model in this version: on the current sample, it won the earlier validation slice, while Random Forest scored better on the final holdout, so the evidence is mixed and does not establish a repeatable winner. The final reported MAE/RMSE/MAPE are computed on the selected model's separate final holdout, pooled across forecastable medicines; training and test observation counts are included. MAPE skips zero actual quantities and is unavailable if every held-out actual is zero. Holt-Winters is not evaluated unless a medicine has at least 24 consecutive observed calendar months; gaps are never filled with invented zeros. All forecastable medicines use one common horizon immediately after the latest actual month. Per-medicine results are summed by that common month to produce the overall chart, which leaves missing historical months blank. Evaluation method, model comparisons, metrics, and charts are stored with each run in the existing private `Backend/runtime/forecast-metadata.json` sidecar; earlier runs without this metadata are shown as unavailable. Restock need equals the forecast-horizon total rounded up minus current stock, floored at zero; no safety buffer is assumed.

Run the forecast unit checks from `Backend/python` with `..\.venv\Scripts\python.exe -m unittest -v`.
