Phase 1.5 — Account Creation + Forgot Password

Continue from the existing Oncophil project.

Phase 1 is currently working. Admin and client login, logout, role-based access, protected routes, profile loading, and Supabase authentication are working correctly.

Do not break any existing Phase 1 functionality.

1. ADMIN USER MANAGEMENT / CLIENT ACCOUNT CREATION

Add a User Management page that is accessible only to admins.

The admin must be able to create client accounts.

The account creation form must contain:

- Full Name
- Email
- Initial Password

When the admin creates an account:

- Create the user in Supabase Authentication.
- Create the corresponding record in public.profiles.
- The new user's role must automatically be client.
- The admin must NOT be able to create an admin account through this feature.
- The new client must be able to log in using the created email and password.
- Do not allow clients to create accounts themselves.
- Do not add a public Sign Up page.

The User Management page should also allow the admin to view existing client accounts, including:

- Full Name
- Email
- Role
- Account status

Handle duplicate emails and other errors with clear messages.

Only admins can access User Management. Clients must be blocked from accessing it even if they manually enter the URL.

SECURITY:

Creating Supabase Auth users requires privileged access.

Do NOT expose the Supabase service-role key in frontend code.

Do NOT put the service-role key in any NEXT_PUBLIC_* environment variable.

Use secure server-side functionality/API routes for creating users if necessary.

Never store passwords in public.profiles or any application table.

Keep the existing RLS policies enabled and do not weaken or disable RLS.

Do not modify the existing admin/client role structure.

2. FORGOT PASSWORD

Add a "Forgot password?" link to the existing login page.

When clicked:

1. Open a dedicated Forgot Password page.
2. Allow the user to enter their email.
3. Use Supabase Auth password reset functionality to send the reset email.
4. After the user opens the reset link, show a page where they can enter a new password and confirm it.
5. After successfully changing the password, return the user to the login page.
6. Handle invalid, expired, or already-used reset links with a clear error message.
7. Show loading, success, and error states.

The Forgot Password feature must work for both admin and client accounts.

Do not add public registration.

3. EXISTING SYSTEM MUST REMAIN WORKING

Do not remove or change the working:

- Admin login
- Client login
- Logout
- Supabase authentication
- Profile loading
- Admin/client role separation
- Protected routes
- Admin workspace
- Client workspace
- Profile pages
- Existing RLS policies

Do not change the existing database schema unless a change is genuinely required for this feature.

4. UI

Use the existing Oncophil design and styling.

Do not redesign the existing application.

The new User Management, Forgot Password, and Reset Password pages should match the current login and workspace design.

Keep the interface simple and professional.

5. SCOPE

This is Phase 1.5 only.

Implement ONLY:

- Admin User Management
- Admin-created client accounts
- Client account viewing
- Forgot Password
- Password Reset

Do NOT implement yet:

- Medicine inventory
- Medicine management
- Orders
- Payments
- Package tracking
- Sales forecasting
- Forecast dashboard
- Other Phase 2 features

After implementation, test all of the following:

1. Existing admin can still log in.
2. Existing client can still log in.
3. Admin can access User Management.
4. Client cannot access User Management.
5. Admin can create a new client account.
6. The new client appears in User Management.
7. The new client can log in.
8. The new client has the client role.
9. Duplicate email creation shows an appropriate error.
10. Forgot Password appears on the login page.
11. A valid email can request a password reset.
12. The reset link opens the password reset page.
13. The password can be changed successfully.
14. The user can log in using the new password.
15. Invalid/expired reset links are handled properly.
16. Logout still works.
17. Protected routes still work correctly.

Run the project's typecheck and build after implementation.

Fix any errors caused by this phase.
