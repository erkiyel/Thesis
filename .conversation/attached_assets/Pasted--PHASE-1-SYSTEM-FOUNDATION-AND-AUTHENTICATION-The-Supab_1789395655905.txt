## PHASE 1 — SYSTEM FOUNDATION AND AUTHENTICATION

The Supabase project has now been created and the database schema has already been successfully applied.

The Replit Secrets already contain:

* `NEXT_PUBLIC_SUPABASE_URL`
* `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
* `SESSION_SECRET`

The Supabase database currently contains the approved 8 application tables:

1. `profiles`
2. `medicines`
3. `orders`
4. `order_items`
5. `payments`
6. `order_tracking_events`
7. `forecast_runs`
8. `forecast_results`

### Goal

Implement ONLY the system foundation and authentication for the Oncophil Pharmaceutical Management System.

Do not implement the other system modules yet.

### 1. Supabase Connection

* Connect the existing application to the Supabase project using the existing environment variables.
* Verify that the application can successfully communicate with Supabase.
* Use the existing database schema as the source of truth.
* Do NOT recreate, modify, or replace the existing database schema.
* Do NOT create additional tables unless absolutely required. If something appears to be missing, explain it before changing the database.

### 2. Authentication

Implement Supabase Authentication with:

* Login
* Logout
* Session handling
* Protected routes

Users must be able to log in using the authentication system.

### 3. User Profiles and Roles

Use the existing `profiles` table.

The system has two roles:

* `admin`
* `client`

After login:

* Load the authenticated user's profile.
* Determine the user's role.
* Admin users must only access admin pages.
* Client users must only access client pages.
* Unauthenticated users must not access protected pages.

Do not allow a client to assign themselves the `admin` role.

### 4. Route Structure

Create a clean route structure for the two user types.

Admin area:

* Admin dashboard/home
* Admin profile/sidebar layout

Client area:

* Client home
* Client profile/sidebar layout

At this phase, these pages only need basic placeholder content/layouts. Do NOT implement inventory, orders, forecasting, tracking, or other modules yet.

### 5. Logout

Implement logout and make sure that:

* The session is properly ended.
* The user is redirected to the login page.
* Protected pages cannot be accessed after logout.

### 6. UI

Create a simple, clean, professional foundation appropriate for a pharmaceutical management system.

Do not over-design the interface yet.

The sidebar should support the future modules, but only the authentication/profile functionality should actually be implemented in this phase.

### 7. Important Scope Restrictions

DO NOT implement yet:

* Machine learning
* Linear regression forecasting
* Forecast charts
* Inventory management
* Medicine ordering
* Payments
* GCash processing
* Cash payment processing
* Package tracking
* Delivery management
* Order archive
* Reports
* Dashboards containing business data
* E-commerce functionality

These will be implemented in later phases.

### 8. Thesis Development Methodology

The development methodology is:

**Waterfall / Linear Sequential Model**

Do NOT use Agile terminology or describe this project as Agile.

Implement this phase completely before moving to the next phase.

### 9. Security

* Never expose the Supabase service-role/secret key.
* Use the existing publishable key.
* Respect the Row Level Security policies already defined in Supabase.
* Do not hardcode credentials.
* Keep environment variables in Replit Secrets.

### 10. Testing

After implementation:

1. Test successful login.
2. Test unsuccessful login.
3. Test logout.
4. Test session persistence.
5. Test unauthenticated access to protected pages.
6. Test admin/client role-based access.
7. Test that a client cannot access admin routes.
8. Test that an admin cannot be treated as a client.
9. Verify the Supabase connection.

If you encounter an error, diagnose and fix it if it is within this phase.

At the end, report:

* What files were created or modified
* What was implemented
* What tests were performed
* Test results
* Any remaining issues
* The exact next step for Phase 2

Do not proceed to Phase 2 automatically.

Do not add features outside this phase.
