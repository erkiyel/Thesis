# THESIS SYSTEM DEVELOPMENT PROMPT

## Project Title

**DESIGN AND DEVELOPMENT OF A PHARMACEUTICAL MANAGEMENT SYSTEM WITH MACHINE LEARNING-BASED SALES FORECASTING FOR ONCOPHIL**

## Project Context

I am a 4th-year BS Computer Science student developing this system as my thesis project for Oncophil.

The system is a pharmaceutical management system with a machine learning-based sales forecasting feature.

The system will have two types of users:

1. **Admin**
2. **Client**

The system must be developed as a real working web application, not just a UI prototype.

## Required Technology / Deployment

The application must use:

* **Supabase** for the backend/database and authentication where appropriate.
* **Vercel** for deployment.
* A modern web frontend framework suitable for Vercel.
* Machine learning-based sales forecasting using **Linear Regression**.

The application must be structured so that the frontend, backend/database, authentication, and machine learning components work together properly.

Do not replace Supabase or Vercel with another service unless I explicitly ask you to.

Do not change the requirements listed below.

---

# ADMIN SIDE

The admin side must contain the following pages/features:

## 1. Login and Logout

* Admin can log in.
* Admin can log out.
* Authentication must properly restrict admin-only pages.

## 2. Admin Profile Sidebar

The admin interface must have a profile sidebar showing:

* Admin name
* Admin picture

## 3. Machine Learning-Based Linear Regression Forecasting

The system must use **Linear Regression** for sales forecasting.

The forecasting functionality must be connected to the sales data stored in the system.

The system should use historical sales data as the basis for generating forecasts.

Do not replace Linear Regression with another machine learning algorithm.

## 4. Admin Home Page

The admin home page must show the sales forecast generated by the machine learning component.

## 5. Inventory Page

The inventory page must show a table of available medicines.

The inventory must allow the admin to view the available medicine records.

## 6. Orders Page

The orders page must allow the admin to:

* Track orders
* See whether an order is paid or unpaid
* Identify the payment method:

  * GCash
  * Cash

## 7. Package Tracking

The admin must be able to see:

* Where the package/order currently is
* An estimated delivery time/date

## 8. Archive of Previous Orders

The admin must have an archive containing previous orders.

---

# CLIENT SIDE

The client side must contain the following pages/features:

## 1. Login and Logout

* Client can log in.
* Client can log out.

## 2. Client Profile Sidebar

The client interface must have a profile sidebar showing:

* Client name
* Client picture

The sidebar must also provide access to:

* Archive of previous purchases

## 3. Client Home Page

The client home page must show available medicines.

Each medicine should have a picture.

Clicking the medicine picture must redirect the client to the ordering page for that medicine.

## 4. Ordering Page

The ordering page must allow the client to:

* Place an order
* Select/pay through the available payment methods:

  * GCash
  * Cash

Payment must be handled through the ordering page.

## 5. Package Tracking

The client must be able to track their package/order.

The client should be able to see:

* Current package/order location
* Estimated delivery time/date

---

# IMPORTANT DEVELOPMENT RULES

1. Do not remove any requirement listed above.
2. Do not add major features that are not listed above without asking me first.
3. Do not change Linear Regression to another machine learning algorithm.
4. Do not replace Supabase.
5. Do not replace Vercel.
6. Build the application as a functional system, not only a visual mockup.
7. Use proper authentication and authorization so clients cannot access admin pages and admins cannot accidentally access client-only functionality.
8. Keep the system appropriate for a 4th-year BS Computer Science thesis.
9. Keep the implementation understandable enough that I can explain it during my thesis defense.
10. Prioritize functionality, security, maintainability, and clear organization over unnecessary visual effects.
11. Do not assume that features such as actual GCash payment processing or real courier GPS tracking are available unless the required integration is explicitly configured.
12. If an external service or API is required for a feature, clearly identify it before implementing it.
13. Do not use fake data in the final system unless it is specifically for testing or demonstration.
14. Keep all sensitive credentials and API keys in environment variables.
15. Never expose Supabase service-role keys or other private credentials in frontend code.

Before writing substantial amounts of code, first analyze these requirements and propose the system architecture, database structure, authentication structure, and implementation plan.
Do not start changing the requirements.
